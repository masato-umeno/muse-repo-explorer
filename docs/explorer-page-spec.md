# エクスプローラーページ仕様

Muse のスペース（Webアーティファクト）として作る、スマホ向けソースコード閲覧ページの仕様。
データは `snapshot.json` の1ファイルに分離し、差し替えるだけで最新化できるようにする。

## データ形式（snapshot.json）

```json
{
  "generated_at": "2026-11-22T10:24:53+09:00",
  "repos": [
    {
      "id": "owner/repo",
      "branch": "main",
      "head": "abc1234",
      "files": [
        {"path": "src/main.ts", "size": 1234, "content": "ファイルの中身（UTF-8テキスト）"},
        {"path": "assets/logo.png", "size": 5678, "skipped": "binary"},
        {"path": "data/huge.json", "size": 999999, "skipped": "large"}
      ]
    }
  ]
}
```

- `content` を持つのはテキストファイルのみ（バイナリと300KB超は `skipped`）。
- 生成は `tools/update_snapshot.py` が担当する。

## UI要件

- スマホ優先レイアウト。日本語UI。ダーク／ライト両対応。
- リポジトリ切替（オーナー別にグループ化したセレクタまたはタブ）。各リポジトリの `branch` と `head` を表示。
- フォルダツリー（展開・折りたたみ）。ファイルをタップで内容表示。
- コード表示：等幅フォント、行番号付き、横スクロール可。軽量なシンタックスハイライト（拡張子による色付け程度で可）。コピー機能があるとよい。
- ファイル名の横断検索：全リポジトリのパスを部分一致で検索し、タップで該当リポジトリに切り替えてファイルを開く。
- `skipped` のファイルはツリーに表示し、開いたら「このファイルは表示できません（バイナリ／サイズ超過）」と案内する。
- スナップショットの生成日時（`generated_at`）を画面内に表示する。
- 初期表示はツリーのみとし、ファイル内容はタップされた時点で描画する（データが大きいため）。
- データ（snapshot.json）はページのコードと分離した単一アセットとして同梱し、差し替えで最新化できる構造にする。

## セキュリティ注意

- スナップショットにはプライベートリポジトリのソースコードが丸ごと含まれる。
  このページは**公開共有（public link）しない**こと。自分専用のスペースとして使う前提。
